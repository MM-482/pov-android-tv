# Cameo Android preview privacy

Cameo is an Android mobile and TV app made by Mark Mateo, based on the original POV project by kodifitzwell. This policy describes the current source implementation. The app has no developer operated account service, advertising SDK, analytics SDK, or developer telemetry endpoint. It communicates directly with the services below. Those services receive normal connection information, including your public IP address, and apply their own policies.

## Connections and information sent

The 0.4.0 working source includes independent playback accounts for TorBox, Real-Debrid, AllDebrid, Premiumize, Offcloud, Debrid-Link, put.io and Easynews. Only the selected playback service receives the selected source/file requests and its own credentials. Easynews member Authorization remains in process memory and is restricted to approved HTTPS Easynews hosts; protected playback uses Media3's guarded redirect path. Other playback adapters use your API credentials. They capture the selected account and reject stale queued actions or results after that account changes.

MDBList (`api.mdblist.com`) receives its own API key, list/read requests, and explicit watchlist/watched actions. Simkl (`api.simkl.com`) receives its own registered app Client ID, device/refresh credentials, library requests, and explicit user actions. **Automatic playback reporting to these two services defaults to Off.** Each account requires a separate consent setting that names the movie/episode identity, playback percentage, and start/pause/stop events sent. Enabling begins with future events only; changing/disconnecting accounts or disabling tracking prevents old unsent work from being sent. This does not alter the existing Trakt connection or tracking behavior.

OpenSubtitles (`api.opensubtitles.com` or its approved VIP API), SubDL (`api.subdl.com`), and SubSource (`api.subsource.net`) receive their own credentials plus the title/episode and preferred language needed for explicit subtitle searches/downloads. The service's approved download hosts receive requests for the selected subtitle. Download quotas can apply. Subtitle credentials are not forwarded to unrelated download hosts. Imported and downloaded subtitles use bounded private app cache files; ZIP paths are never extracted into arbitrary filesystem locations. Android's document picker grants access to the file selected by the user rather than broad storage access.

Player, preferred-language, and selected playback-service choices are nonsecret local preferences. New credentials and pending optional-tracker updates use the same encrypted account store and backup exclusions described below. The VLC library is embedded for playback and does not introduce a Cameo-operated account or analytics service. See [0.4.0 setup](INSTALL_0.4.0.md) for configuration and limitations.

The mobile and TV appearance choices use locally bundled fonts and generated design-preview images. Choosing a theme does not contact Google Fonts or an image-generation service. Home still loads catalog artwork through the artwork hosts below. The generated picker references contain fictional sample titles rather than the user's viewing history.

The unmodified VideoLAN dependency includes upstream playlist adapters with public SoundCloud and Twitch client identifiers. These are third-party library content, not Mark Mateo's or your account credentials. Opening a URL handled by such an adapter can contact that third-party service. Cameo does not ask for SoundCloud or Twitch account credentials. The artifact checker records matching upstream files by exact path and SHA-256; that provenance classification is separate from checking Cameo's own account configuration.

Account information is shared with the service it authorizes for the functions above. Viewing progress and watched status are sent to Trakt when that account is connected and the playback has a matched identity. The app does not send your account tokens or viewing history to a Mark Mateo server. The app does not control third party logging, retention, or subsequent use.

## Information kept on the device

- Account and connection settings are stored in the app's private preferences encrypted using AES-GCM with an Android Keystore key. This includes playback-service API keys/tokens and the Easynews username/password; Trakt and Simkl app identifiers and tokens; the MDBList API key; subtitle-service keys, credentials and tokens; callback configuration; and a custom source provider address. The key is not exported by the app. This is not a guarantee against a compromised device or operating system.
- Recent playback keeps up to 40 records containing title, media identity when available, local source key, playback position, and duration. Failed Trakt updates are queued locally for retry. **These playback preferences are private to the app but are not additionally encrypted by Cameo.** They can contain cloud file titles or viewing history.
- The chosen theme is saved as a normal, nonsecret device preference. Public catalog metadata also has a bounded disk cache (200 entries / 24 MiB, six-hour freshness and seven-day offline fallback); account responses, stream resources and credentials are excluded. Explicitly downloaded videos are written to a document selected by the user. Local library, watchlist, playlists and download-job metadata use the encrypted account store. These can include private titles, provider file IDs, destination document URIs and server references, but not resolved playback addresses or request headers.
- Simkl library responses and activity snapshots are cached in the encrypted account store for incremental refreshes. Studio's Trakt Up Next results use an account-bound in-memory cache with a five-minute refresh interval while Home is revisited.
- The active playback URL is used in memory and the private player Activity's intent. Recent playback records do not store the resolved streaming URL. Android manages Activity/process state independently of Cameo.

The manifest sets `android:allowBackup="false"`. It also supplies explicit exclusion rules for all supported app storage domains: credential protected and device protected files, databases, preferences and root storage, plus app specific external storage. On Android 12 and later, both the standard cloud backup and device transfer sections exclude all of this app data. A separate legacy rules file applies on Android 11 and earlier. This covers encrypted account settings, local playback history, pending Trakt updates and appearance preferences through the standard Android backup mechanisms. Android documents why device transfer rules are needed in addition to the manifest flag on some manufacturers' devices. [Android backup configuration](https://developer.android.com/identity/data/autobackup), [Android 12 backup changes](https://developer.android.com/about/versions/12/behavior-changes-12#backup-restore).

These settings do not control a manufacturer's nonstandard migration tools, debugging access, a compromised or rooted device, operating system behavior outside the standard backup rules, or separately captured screenshots/logs. The preview build is intended for sideloading and may be debug signed; do not treat a development device as a vault.

## Removing information

Settings can disconnect each playback or tracking account. Disconnecting invalidates in-flight connection attempts and account-bound requests. Disconnecting Trakt or changing its Client ID also discards unsent Trakt updates through the app UI. Disabling the optional MDBList/Simkl playback reporting or changing/disconnecting those accounts clears or invalidates their unsent updates. Disconnecting does not erase your local recent playback list, delete remote cloud transfers, erase remote watch history, or revoke every authorization held by a remote service. Simkl attempts to revoke its own grant; remote access and other sessions remain subject to the service. Manage remote access and account history in those services.

Android's app storage controls can clear Cameo's local app data, and uninstalling normally removes its local preferences. Reinstalling, restoring, and manufacturer behavior can vary. Never share account tokens, activation codes, private cloud/download URLs, or screenshots of personal viewing history in public bug reports.

## Source and release preparation

Release source packaging uses an explicit file allowlist. TV verification captures, inspection material, tooling, local machine settings, runtime app preferences, and private signing keys are excluded. The offline public-artifact checker examines archive entries and detectable strings; it does not read a TV's account data. A passing static check cannot prove the absence of every secret, inspect visual content in images/video, verify third party behavior, or replace review of the exact files being published.

Report a privacy concern through the issue tracker of the repository distributing your build, with a sanitized description. Do not attach credentials or private playback links. Publication remains a separate review action from preparing a local release bundle.

## Cameo desktop-feature additions

Media-server connections (Plex, Jellyfin, Emby, WebDAV and eligible-plan Seedr) receive their own credentials and explicit browse/search/playback requests. AniList, MyAnimeList and Kitsu account connections receive their own credentials, list reads, and explicit status/progress/score edits. Their account IDs are not silently treated as IMDb IDs. Saved account profiles and configured add-on manifests are encrypted. An add-on address may itself contain private configuration; never share it in a report or screenshot.

Installed compatible add-ons receive the selected resource's exact catalog/title/video identifier and supported search/genre/offset values. Direct stream hosts may require validated authorization headers. These stay in process memory and are bound to their original origin; unsupported transport requirements are rejected. Public metadata lookup does not automatically create a cloud transfer. The user selects and confirms preparation where a transfer may be added. Remote servers require HTTPS. Explicitly configured local HTTP servers send their requests over the local network without TLS.

Local import uses Android document grants instead of broad storage permission. Folder scanning can be cancelled. Open/shared videos require an explicit import action. A provider with only a temporary grant may become unavailable later; Cameo does not copy every imported video into its own storage. Downloads use a chosen new/empty destination, and partial files can remain after cancellation or failure. Download metadata is encrypted; video contents are not additionally encrypted by Cameo at their chosen location. Jobs interrupted by process death are labelled Interrupted rather than silently resumed.

Remembered subtitle selections copy validated text into durable app-private files and store their exact title/episode identity, enabled state and timing in encrypted metadata. Text subtitle contents are app-private files, without an additional encryption layer. Unsaved connection forms survive an in-process fold/window rebuild in memory, including secret fields; these drafts are not written into saved activity state, preferences, diagnostics or logs.

VLC Cast discovery runs only from the explicit player action, on the local network, for a bounded scan. Selecting a receiver sends the current compatible media session through VLC output; the receiver and media host may receive playback/network information. Header-protected sources are refused. Receiver names are excluded from diagnostic export and normal playback starts no background discovery. This is separate from Android's explicit PiP option and the in-app mini-player.

The troubleshooting exporter uses a deliberate allowlist: app version, Android/device/engine information and connection booleans. It excludes account names, credentials, request headers, source URLs, filenames/paths, titles and viewing history. Saving is explicit and nothing is uploaded automatically. Static public-package scans supplement exact file review; they do not establish third-party behavior or the security of a compromised device.
